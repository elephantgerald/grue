### Important

**I-1. Missing fall-through integration test for the refactored `v-take` `:trytakebit` branch** (pr-test-analyzer)
- The PR changed the guard from `(= :m-handled (object-action obj-key :take))` to `(dispatch-action obj-key :take)`. The *pre-empt* direction is covered end-to-end (`west_of_house_test.clj:87` — mailbox "It is securely anchored."). The *fall-through* direction (a `:trytakebit` object whose action does NOT block, so the take succeeds) is only tested in isolation, and with a mismatched verb (`dispatch-action :sword :lamp-on`).
- `:sword` is the ideal subject — it has both `:trytakebit` and `:action :sword-fcn` (no handler) (`1dungeon.edn:1320`). A regression making the `:trytakebit` clause truthy-by-accident would silently make every such object un-takeable while the suite stayed green (the only integration case, the mailbox, is *supposed* to be blocked).
- **Recommend:** add an integration test `take-trytakebit-object-with-no-blocking-handler-succeeds` — place `:sword` in an accessible room, assert `"Taken."` and that `:sword` location becomes `:winner`.

**I-2. The `:m-handled` sentinel check was loosened to bare truthiness — couple print with pre-empt** (silent-failure-hunter)
- `v-take` previously pre-empted only on `(= :m-handled ...)`; this PR loosened it to any truthy `dispatch-action` return (actions.clj:528-530), matching the `v-lamp-on`/`v-lamp-off` pattern.
- Bare truthiness is actually *more* ZIL-faithful (ZIL PERFORM treats any non-false return as RTRUE), so reinstating the sentinel is not necessarily right. The genuine hazard is the **print-but-return-nil** mistake: a future handler that does `(case verb :take (println "..."))` prints its message, returns `nil`, falls through, and the verb ALSO prints/acts → double output + wrongful take. Only `:mailbox-f` exercises this today, but ~30 `:trytakebit` objects will route through it as handlers are written.
- **Recommend:** introduce a tiny helper that makes the print and the truthy return inseparable, e.g. `(defn- handled [& msg] (apply println msg) :m-handled)`, and write blocking handlers as `(handled "It is securely anchored.")`. Add a regression test asserting a print-then-nil handler does NOT suppress the verb.

### Suggestions

**S-1. `:default` silently swallows typo'd / unimplemented `:action` values** (silent-failure-hunter)
- ~90 distinct `:action` values exist in `1dungeon.edn`; only `:lantern` and `:mailbox-f` have handlers. Every other value (and any misspelling, e.g. renaming `:lantern` without updating the EDN) routes to `(defmethod object-action :default [_ _] nil)` (actions.clj:317) — a permanent silent no-op with no error. Mirrors the pre-existing `room-action` `:default`, so not a regression, but the dispatch key being a hand-maintained keyword in a separate data file makes typos realistic.
- **Recommend (optional, pattern-level):** a `load-world!` validation that every `:action` value is either a registered method or on a deliberate "deferred" allowlist — catches typos at load time. At minimum, note in the `:default` comment that this path hides typos.

**S-2. Handlers don't receive the object key; `:lantern` hard-codes `:lamp`, `:mailbox-f` drops the PRSO identity guard** (code-reviewer, silent-failure-hunter)
- `object-action` dispatches on `(action verb)` only. `:lantern` reads `(get-object :lamp)` directly (ZIL-faithful — LANTERN references `,LAMP`), and `:mailbox-f` checks only `(= verb :take)` whereas ZIL `MAILBOX-F` guards with `<AND <VERB? TAKE> <EQUAL? ,PRSO ,MAILBOX>>` (1actions.zil:2260). Safe today because each `:action` value is carried by exactly one object, but if a value is ever reused (copy-paste content work), a handler would make decisions about the wrong object, silently.
- **Recommend (forward-looking):** pass `obj-key` into `object-action` (`(defmulti object-action (fn [action _obj-key _verb] action))`) so handlers reference the dispatched object — mirrors ZIL's PRSO availability and lets `:mailbox-f` restore the identity guard.

**S-3. `dispatch-action` precondition (resolved object) is undocumented** (code-reviewer, silent-failure-hunter)
- `get-object` throws on an absent key (actions.clj:46-50) and `dispatch-action` calls it unguarded. Unreachable today — the parser yields a real key or `:not-found`, which `perform` short-circuits before any verb handler. But `dispatch-action` is public and documented as PERFORM's ACTION call; if wired into a PERFORM-style first-dispatch on an unparsed PRSO, the throw becomes reachable (ZIL's `APPLY <GETP ,PRSO ,P?ACTION>` no-ops gracefully).
- **Recommend:** add a one-line docstring noting the precondition that the object key must be resolved.

(Suggestion — false authority is corrosive, but a comment-only issue.)

The Clojure healthy path returns nil and the timer enable/disable is not modeled anywhere. Out of scope for #48, but the comment frames the healthy case as a pure pass-through, hiding the deferred behavior. **Recommend:** add a NOTE that the I-LANTERN timer toggle is not yet modeled. (Suggestion)
